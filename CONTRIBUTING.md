# Как разрабатывать (sigma-assistant)

Здесь живут **бэкенд ассистента** (`server.py` — RAG-тулзы, прокси к LLM) и
**бенчмарк** (`eval/`). Фронтенд виджета — в репо `sigma` (`docs/assistant/`).

## Два контура

| | ветка | что | кто мержит |
|---|---|---|---|
| **Прод** | `master` | сервис за https://sigma.fmin.xyz/api/ | после ревью Дани |
| **Стенд** | `dev` | отдельный сервис за https://sigmadev.fmin.xyz/api/ | команда, песочница |

Dev-инстанс полностью изолирован: свой процесс, свой OpenRouter-ключ,
свой индекс глав из dev-ветки учебника — тестируйте свободно.

## Флоу

1. Ветка **от `dev`**: `git fetch origin && git switch -c fix/моя-задача origin/dev`.
2. PR с base **`dev`**. Описание: что сделал, как проверял.
3. После мержа GitHub Actions (вкладка **Actions → «Deploy dev stand»**)
   рестартует dev-сервис на сервере за секунды (фоллбэк-cron — до 5 минут).
4. Проверяешь на живом стенде:
   - чат-виджет на любой главе https://sigmadev.fmin.xyz
   - API напрямую:
     ```bash
     curl -s -X POST https://sigmadev.fmin.xyz/api/textbook/search \
       -H 'Content-Type: application/json' -d '{"query":"Ньютон"}'
     ```
5. Обкатал на стенде → PR в `master` на ревью.

Серверных логов у вас нет (нужен доступ к VPS) — если после деплоя что-то
непонятно себя ведёт, пишите в чат, пришлём кусок лога.

## Бенчмарк

Всё про запуск, версии, артефакты и грейдинг — **`eval/README.md`**. Коротко:

- прогон запускается только с сервера (меняет модель живого сервиса) —
  попросите в чате; результаты сразу на https://sigmadev.fmin.xyz/benchmark;
- **версия бенча = папка** `eval/bench_v<N>`. Правило: одна папка — один
  датасет и один агент. Меняете `eval/cases.jsonl` ИЛИ промпт/цикл агента →
  это **новая версия** (`--version v<N+1>`), старые результаты не трогаются;
  раннер сам откажется писать в чужую версию. Страница: последняя версия на
  `/benchmark/`, старые — `/benchmark/v1/`, `/benchmark/v2/`, … (переключатель
  в шапке);
- перескорка сохранённых ответов — **только `eval/grade_hybrid.py`**
  (`regrade.py` — шим на него). Смысловые кейсы судит Claude по точному
  sha1 ответа; несудимый ответ показывается как **⏳ «ждёт судью»** и не
  входит в статистику — это не провал и не зачёт;
- принцип: бенч должен **ловить** дефекты модели, а не маскировать их;
  сохраняем максимум артефактов (диалоги, графики, трейсы — см. README).

## Гигиена

- В дифф не должны попадать артефакты окружения (локальные пути, логи, `.env`).
- id кейсов в `cases.jsonl` уникальны — проверяйте перед PR.
- Один PR = одна тема; грейдер и датасет — отдельными PR (их мержат в разном порядке).
