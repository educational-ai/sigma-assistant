## 1. Расширить eval-набор бенчмарка агента
**Что:** добавить ≥25 новых вопросов-кейсов в `eval/cases.jsonl` по реальным главам учебника (сейчас всего 29 — мало для надёжного сравнения моделей). Каждый кейс: вопрос, категория, `expected_tools`, `expected_answer_contains`/`excludes`, при нужде `expected_visual`.
**Зачем:** бенчмарк сравнивает LLM на нашем RAG-агенте; узкий набор = шумные выводы.
**Дедлайн:** 2026-06-19 (Пт).
**Критерии приёмки:** ≥25 валидных кейсов; покрыты ≥6 разных глав и все категории (rag_basic / definition / compute_pure / compute_plot / multi_hop / structural / out_of_scope); каждый кейс проходит на эталонной модели (`python3 bench_models.py <model>` → pass); PR в приватный репо, не ломает существующие 29.
**Профиль:** Python + понимает предметку (опт/ML/линал).

## 2. Визуальный судья ответов (vision QA на масштабе)
**Что:** на базе готового `eval/render_answer_shots.py` (рендерит каждый ответ в PNG как видит читатель) построить пайплайн: скриншот → vision-модель → вердикт визуальной адекватности (битые формулы / кривые переносы / поехавшие таблицы / треш-стиль) по всем моделям и кейсам, отчёт в markdown.
**Зачем:** текстовый/substring-грейдер пропускает визуальный мусор (был инцидент: 100% на нечитаемом ответе).
**Дедлайн:** 2026-06-24 (Ср).
**Критерии приёмки:** per-answer вердикт (ок / дефект+тип) для всех 19 моделей; сводный отчёт «сколько визуальных дефектов у каждой модели»; ложноположительных <10% на ручной выборке из 30; запускается одной командой.
**Профиль:** Python + LLM/vision API.
